# نص شرح مخطط FoxFlow أمام اللجنة

مدة الشرح المقترحة: 4 إلى 6 دقائق.

## المقدمة

> مشروع FoxFlow هو منصة DevSecOps متكاملة. نستخدم GitLab كمنصة العمل الرئيسية للفريق، بينما نستخدم GitHub لحفظ نسخة أرشيفية من الملفات. عند رفع أي تعديل إلى GitLab تبدأ عملية الفحص والنشر تلقائيًا.

## أولًا: عمل الفريق وGitLab

أشر إلى الجزء العلوي الأيسر من المخطط.

> يبدأ العمل من أعضاء الفريق. كل عضو يعمل بحسابه ومفتاح SSH الخاص به، وينشئ فرعًا ثم يرفع التعديل إلى GitLab. بعد المراجعة ودمج التعديل في الفرع الرئيسي تبدأ Pipeline تلقائيًا. GitHub ليس مسؤولًا عن التشغيل؛ هو نسخة حفظ إضافية للكود.

## ثانيًا: مراحل Pipeline

أشر إلى المراحل الخمس بالترتيب.

> المرحلة الأولى هي Build، وفيها نبني صورة Docker ثابتة للإصدار. المرحلة الثانية Test لتشغيل اختبارات التطبيق. المرحلة الثالثة Security، وفيها يفحص Trivy الصورة ويمنع النشر عند وجود ثغرات خطيرة. المرحلة الرابعة Deploy لإرسال الإصدار المقبول إلى Azure. المرحلة الخامسة Notify لإرسال النتيجة للفريق.

## ثالثًا: Azure والحماية

أشر إلى المنطقة الزرقاء في يمين المخطط.

> يعمل النظام على Azure VM داخل حدود شبكة محمية. يسمح Network Security Group بالمنافذ المطلوبة فقط. يستقبل Caddy اتصال HTTPS، ثم يمرر الطلب إلى تطبيق FoxFlow على منفذ داخلي غير مكشوف للإنترنت. تحفظ المستودعات والصور والسجلات على قرص بيانات دائم.

## رابعًا: عرض النتائج

أشر إلى الصف السفلي.

> يستطيع الفريق متابعة النتيجة من لوحة FoxFlow دون الدخول إلى GitLab. تعرض اللوحة حالة Pipeline والاختبارات وفحص الأمان والنشر. نظام المراقبة يفحص الخدمات باستمرار. عند حدوث فشل يقرأ OpenRouter تفاصيل الخطأ ويستخرج السبب والحل المقترح، ثم يرسل Telegram النتيجة للفريق فورًا.

## خامسًا: النسخ الاحتياطي

> يأخذ النظام نسخة احتياطية يومية من بيانات GitLab، ويرفعها إلى Azure Blob Storage مع التحقق من سلامتها. لذلك يوجد لدينا استرجاع مستقل حتى عند تعطل الخادم الأساسي.

## الخاتمة

> النتيجة هي دورة تطوير كاملة ومؤتمتة: تعاون في GitLab، بناء واختبار وفحص أمني، نشر آمن عبر HTTPS، متابعة مرئية، تحليل ذكي للأخطاء، تنبيه فوري، ونسخ احتياطي قابل للاسترجاع.

## سيناريو العرض الحي

1. افتح GitLab واعرض مستودع `sample-app`.
2. نفّذ تعديلًا بسيطًا على التطبيق وارفعه إلى GitLab.
3. افتح صفحة Pipeline وأظهر انتقال المراحل الخمس.
4. بعد النجاح افتح تطبيق FoxFlow عبر HTTPS.
5. افتح `/dashboard` واعرض النتيجة دون الرجوع إلى GitLab.
6. افتح Telegram واعرض رسالة النجاح أو تحليل فشل سابق.
7. اختم بعرض `/health` لإثبات جاهزية الخدمة.

## إجابات مختصرة لأسئلة متوقعة

### لماذا GitLab؟

لأنه يجمع المستودع، مراجعة الكود، Pipeline، Runner، Container Registry، السجلات والصلاحيات في منصة واحدة.

### لماذا GitHub موجود؟

لحفظ نسخة أرشيفية إضافية من ملفات المشروع، وليس لتشغيل Pipeline.

### ماذا يحدث إذا فشل الاختبار أو الفحص الأمني؟

تتوقف Pipeline قبل النشر، ويصل للفريق إشعار يحتوي على الخطأ وتحليل AI والحل المقترح.

### هل التطبيق مكشوف مباشرة للإنترنت؟

لا. التطبيق يعمل على منفذ داخلي، والوصول الخارجي يتم من خلال Caddy وHTTPS فقط.

### كيف نعرف أن النظام جاهز؟

من لوحة التحكم، تنبيهات Telegram، ونقطة الفحص `/health` التي تعيد حالة الخدمة.
