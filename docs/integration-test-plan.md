# اختبار نشر العضو ٤

## تجربة محلية قابلة للإعادة

من جذر المستودع، مع تشغيل Docker Desktop وتوفر curl وjq:

```bash
bash scripts/test-deploy-local.sh
```

على Linux استخدم `LOCAL_DOCKER_CONTEXT=default` إذا كان هذا هو سياق Docker المحلي.
السكربت يرفض أي سياق لا يستخدم Unix socket، ويستخدم اسم Compose فريدًا ومنفذًا عشوائيًا على 127.0.0.1، ثم يزيل حاوياته وشبكته عند الانتهاء. لا يستخدم أسرارًا أو SSH أو خادم Azure. تبقى صورة node:24-alpine في مخزن Docker المحلي لإعادة الاستخدام.

الملفات في tests/deploy-fixture تطبيق اختبار مستقل وليست تطبيق العضو ٣. يجري الاختبار على ملف Compose الحقيقي مع إضافة أمر تشغيل التطبيق المؤقت وتقصير مدد فحص الصحة؛ نص فحص الصحة نفسه لا يتغير. لهذا لا يقيس الاختبار مدد انتظار الإنتاج الفعلية.

## اختبار التكامل بعد جاهزية العضوين ٢ و٣

ينفذ أولًا على مشروع وبيئة تجريبية، قبل تشغيل النشر على production.

| الخطوة | معيار النجاح | الدليل المطلوب |
| --- | --- | --- |
| CI Lint على GitLab الفعلي | يقبل ملف YAML | نتيجة lint وإصدار GitLab |
| مزامنة sample-app | package.json و.gitlab-ci.yml في جذر GitLab | رابط commit |
| Pipeline مع DEPLOY_ENABLED غير مفعّل | Build ثم Test ثم Scan تنجح؛ Deploy غير موجود | رابط Pipeline |
| جعل اختبار التطبيق يفشل عمدًا في نسخة تجريبية | Test يفشل، ولا يحدث Deploy | رابط Pipeline قبل إعادة التعديل |
| فحص صورة تجريبية مع ثغرات HIGH/CRITICAL | Scan يفشل، ولا يحدث Deploy | سجل Trivy ورابط Pipeline |
| فشل أداة الفحص أو تعذر تحميل قاعدة الثغرات | Scan يفشل والنشر محجوب | سجل الفشل |
| فرع غير افتراضي أو غير محمي | Deploy غير موجود حتى لو DEPLOY_ENABLED=true | رابط Pipeline |
| نشر على الفرع الافتراضي المحمي بعد نجاح البوابات | Compose يصل إلى healthy | سجل Deploy وصورة commit المنشورة |
| فحص الوصول الخارجي | /health يعيد 200 وJSON | curl مع الوقت والعنوان دون أسرار |
| نشر نسخة تجريبية غير سليمة | Deploy يفشل خلال مدة الانتظار | سجل Deploy؛ معالجة يدوية للنسخة غير السليمة |
| Notify بعد نجاح وفشل | التقرير يحوي رابط Pipeline دون ادعاء نجاح نشر | pipeline-summary.txt |
